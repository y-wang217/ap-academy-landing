# REQ-34: Feedback 8: The Notion Weekly Schedule says it is generated after adoption and links to the editor

Card: https://app.notion.com/p/3fbd6ae73dd78131b118e42781f8ecd1 (design approved there on 2026-10-22, after two revise rounds; this is the build copy).

**Summary:** once a student is adopted, the scheduler also writes one line to the Students & Parents property **Schedule Source** saying the schedule is generated, since when, and where to change it, while Weekly Schedule keeps slot lines only; and the Weekly schedules page shows Charlie a "Notion edits replaced" notice listing students whose hand edit was overwritten since he last marked them seen, with the replaced text.

**Risk:** Medium (two new columns on `tracker.schedule_summaries` behind its existing owner-only RLS, and one more property on a Notion write path the scheduler already uses; no auth, permission or personal-data change, and the line holds a date and a link only).

**Decision behind it:** Charlie chose option B on 2026-10-22: leave Weekly Schedule alone (billing's `parse_slot` raises on any non-slot line) and write the notice to a new text property, Schedule Source. The owner drift notice stays in this card.

## Problem
From the 2026-10-16 readiness review, finding F02. After adoption, `apps/tracker/lib/scheduler/summary-sync.ts` overwrites any hand edit to a student's Weekly Schedule with the generated summary and keeps the replaced text in `last_drift_text`. Before adoption the same field is the input. Nothing in Notion says which mode a student is in, so an edit made after adoption looks accepted until the next sync replaces it. The only place the replaced text shows is a collapsed "Replaced edit" line in the Imported list, with nothing telling Charlie that something new was replaced.

## Acceptance criteria
- [ ] AC1: `scheduleSourceLine({ adoptedOn, staffIds, siteUrl })` returns exactly `Generated by the scheduler since <adoptedOn>. Edits to Weekly Schedule are replaced. Change classes at <url>` where `<url>` is `<siteUrl>/tracker/schedule?staffId=<id>` when every open series has one teacher, and `<siteUrl>/tracker/schedule?view=all` when there are several. The line has no newline, no em dash, and is at most 2,000 characters.
- [ ] AC2: After a sync of an adopted student, Notion holds Weekly Schedule equal to `renderSummary(...)` (slot lines only, unchanged from today) and Schedule Source equal to the AC1 line, where `adoptedOn` is the Toronto date of `schedule_summaries.adopted_at`.
- [ ] AC3: The scheduler never writes Schedule Source for a student who is not adopted: `syncStudentSummary` returns `skipped` with zero Notion writes, and no other code path PATCHes it.
- [ ] AC4: When Weekly Schedule and Schedule Source both differ from Notion, one PATCH sets both. When only one differs, the PATCH carries only that property. When neither differs, no PATCH is sent. A retry after a write that committed but reported an error writes nothing (REQ-35 AC6 still holds).
- [ ] AC5: Drift detection is unchanged: it compares only Weekly Schedule with `last_written_text` (or `adopted_from_text`), never Schedule Source. A Schedule Source that someone edited by hand is put back to the line with no drift recorded. Existing `summary-sync.test.ts` cases AC13 and AC15 pass unchanged.
- [ ] AC6: The existing monthly-admin compat test stays green, and a new case parses an adopted student's Weekly Schedule written by the sync with the compat `parse_slot` port without error.
- [ ] AC7: `students.ts` still has exactly one `method: "PATCH"`, and its body names only Weekly Schedule and Schedule Source. `fetchStudentSchedule` asks for Student Name, Stage, Weekly Schedule and Schedule Source only; `fetchScheduledStudents`, `fetchStudentNames`, `fetchStudentPeople` and `fetchScheduledStudentNames` do not ask for Schedule Source.
- [ ] AC8: When a sync records drift, `last_drift_at` is set to that time along with `last_drift_text`. A sync with no drift leaves both unchanged.
- [ ] AC9: The Weekly schedules page (`/tracker/scheduler/schedules`) shows a "Notion edits replaced" card when at least one adopted student has unseen drift. A row is unseen when `last_drift_text` is set and (`drift_seen_at` is null, or `last_drift_at` is not null and `drift_seen_at < last_drift_at`). Old drift with a null `last_drift_at` shows until it is marked seen once, then stays hidden. Each row shows the student name, the date it was replaced (or "Before this notice existed") and the replaced text. With no unseen drift the card is not shown.
- [ ] AC10: "Mark as seen" (`POST /api/scheduler/summaries/drift-seen`, owner only, body `{ items: [{ studentId: guid, lastDriftAt: string | null }] }` of 1 to 200 items, each `lastDriftAt` exactly as the preview returned it) sets `drift_seen_at = now()` on each row whose `last_drift_at` is not distinct from the posted value; the card then hides them; a later drift on the same student shows it again. A row whose `last_drift_at` changed after the page loaded is not updated and stays listed after the reload. The response is `{ updated: n }`. A teacher gets 403 and nothing is written; a bad body gets 400; an id that is not adopted is ignored.
- [ ] AC11: The card says that a Notion edit is not a calendar change and that classes change in the schedule. No path turns drifted text into a series, exception or calendar change.
- [ ] AC12: `supabase/tests/scheduler_import.sql` shows the owner can update `last_drift_at` and `drift_seen_at` on their org's rows, a teacher and another org's owner cannot read or update them, the columns are null on a new adoption, and an owner update filtered on a stale `last_drift_at` changes 0 rows and leaves `drift_seen_at` as it was.
- [ ] AC13: Tracker ADR `0067-schedule-source-and-drift-notice.md` exists with every section, is in the decisions `README.md`, has no em dash, and records that Schedule Source is write-only for the scheduler (never parsed, never a drift input, never read by billing or the daily task).

## Approach
- **Line builder (new, pure):** `apps/tracker/lib/domain/schedule/source-line.ts`. Teacher ids are deduped; one id gives `?staffId=`, more or none give `?view=all`.
- **Notion module:** `apps/tracker/lib/notion/students.ts`. New constant `SOURCE = "Schedule Source"`. `StudentRecord` gains `scheduleSource` (empty when absent). `fetchStudentSchedule` asks for the four properties; the list and name paths keep their lists. `writeWeeklySchedule` becomes a thin wrapper over a new `writeStudentSchedule(config, pageId, patch, fetcher)` that holds the file's one PATCH, refuses an empty patch, applies `MAX_SUMMARY_CHARS` to each value, and sends only the keys given.
- **Sync:** `StudentsPort.write(pageId, patch)`. `SyncDeps` gains `siteUrl` (from `SITE_URL`). The line uses the staff of open series (`effectiveUntil` null or on or after today). Drift is computed as today, on Weekly Schedule only. The patch holds `weeklySchedule` if the text differs and `scheduleSource` if the trimmed source differs; an empty patch marks `synced`. The no-series guard is unchanged. `payloadHash` hashes text plus newline plus line. Drift also passes `lastDriftAt`.
- **Wiring:** `lib/scheduler/deps.ts`, `app/api/scheduler/daily-task/run/route.ts`, `app/api/scheduler/payout-guardrails.test.ts`, `lib/scheduler/outbox-wiring.ts`.
- **Store and data:** `SummaryRecord` gains `lastDriftAt` and `driftSeenAt`; `SummaryPatch` gains `lastDriftAt`; new `markDriftSeen(items)` returning the rows changed. Null items go in one update (`in` ids, `is last_drift_at null`, `not last_drift_text is null`); each timestamped item gets its own update with `eq notion_student_id` and `eq last_drift_at <posted string unchanged>`, run with `Promise.all`. A query error throws.
- **Owner notice:** `lib/domain/schedule/drift-notice.ts` (`unseenDrift`, newest first, null drift time last). The import preview's `adopted` items gain `lastDriftAt` and `driftSeen`. New `handleDriftSeen` (admin; strict body; duplicate ids 400) and route `app/api/scheduler/summaries/drift-seen/route.ts`. `components/scheduler/schedule-import.tsx` gets a "Notion edits replaced" card above Imported: the two copy lines, one row per student (name, "Replaced <date>" or "Before this notice existed", the replaced text), and Mark as seen ("Saving..." while saving, "Could not save. Try again." on error with the card kept, reload on success). The collapsed "Replaced edit" line in Imported stays as history.
- **e2e mock:** Students schema adds Schedule Source; page responses include it; a PATCH keeps each property it names, and writes are counted as before.
- **Docs:** tracker ADR 0067 plus its README row; `docs/readiness.md` F02 updated.

## Migration
`supabase/migrations/0026_schedule_drift_seen.sql`, additive only (two `add column`, one column `grant update`), so not a human migration. Ships first in its own PR (`req/REQ-34-migration`, #114), human-merged; after Charlie signs off it is applied through the Supabase MCP `apply_migration` as `0026_schedule_drift_seen`. No new policy and no backfill. Check: `supabase/tests/scheduler_import.sql`.

## Out of scope
Changing what the Weekly Schedule summary contains, removing the Notion field, or changing the monthly billing skill. Cutover rules for edits made during migration. A per-student filter on `/tracker/schedule`. Clearing Schedule Source. A drift count on the setup page. Turning a hand edit into a calendar change, in any form.

## Decisions (defaults approved)
1. No new dependencies. 2. Migration 0026, tracker ADR 0067. 3. "When" is the adoption date. 4. Link: one teacher by staffId, else view=all. 5. The line as written in AC1. 6. Same PATCH through `writeStudentSchedule`, with `writeWeeklySchedule` as a wrapper. 7. Schedule Source is read in the one-page fetch only, to decide whether to write. 8. Payload hash covers text and line. 9. Two timestamps, no backfill. 10. Explicit Mark as seen that posts each row's `lastDriftAt` and updates only matching rows. 11. Notice on the import page only. 12. Keep the "Replaced edit" line. 13. Change the port shape in the daily-task run route (human-merge path). 14. Risk Medium.
