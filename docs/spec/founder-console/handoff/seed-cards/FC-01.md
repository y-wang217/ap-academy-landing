# FC-01 — Founder Console source-of-truth audit and route decision

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P0  
**Risk:** Low (designer must re-evaluate against current code and policy)  
**Initial status:** Ready  
**Blocked by seed cards:** none

## Outcome
Record the exact existing auth, CRM, scheduling, trial, follow-up, payment, media-task and event contracts needed by the console, with a decisive app placement plan.

## Scope
- Read current root/per-app CLAUDE.md, ADRs, open req PRs and all relevant implementations
- Identify source systems, stable identifiers, data freshness and existing permissions
- Choose same-origin path/app strategy, surface design decisions, and record missing evidence
- Do not change app code or live data; deliver a concise ADR/spec or equivalent allowed docs change

## Acceptance criteria
- AC1: Decision record gives a current file path, function/API and authority for each of the 8 core data domains, or marks as undiscovered with reproducible evidence.
- AC2: Proposed console route reuses the current one-domain auth/session pattern and identifies how unauthorized staff are rejected server-side.
- AC3: Existing overlap with planned/in-progress REQ cards is reconciled and mapped, not duplicated.
- AC4: Freshness, missing-source and external side-effect risks are documented and mapped to downstream cards.
- AC5: A source-backed strategy exists for verified recurring-hour computation or a defined "unverifiable" fallback.

## Required test coverage
- T1: Reviewer inspects source-path citations for AC1/AC2 and can reproduce at least one data-flow trace.
- T2: Docs scope test verifies no app/DB/schema changes were made for this card.
- T3: Independent reviewer checks every downstream assumption against documented unknowns.

## Explicit non-goals
- No new product UI, schema, permissions or external integrations.

## Design-stage obligations
Read current repo and Notion schema; map actual files and authorities; confirm dependencies and Risk; use the active `docs/designs/_TEMPLATE.md` for the implementation design on the real card; give each AC a test row; reserve migration/ADR numbers only via current pipeline rules. Never skip human approvals for High risk or migrations. See `03_ENGINEERING/ARCHITECTURE_AND_DATA.md` and `02_DESIGN/VISUAL_DIRECTION.md`.
