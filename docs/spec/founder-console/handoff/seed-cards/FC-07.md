# FC-07 — Teacher load, trial funnel, verified financial readouts and delivery gaps

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P1  
**Risk:** Medium (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-03, FC-04

## Outcome
Make staffing availability, trial outcomes, lesson-log gaps and payment verification visually inspectable without assuming unverified facts.

## Scope
- Read from existing teacher roster, adopted schedules/availability and completed lesson logs
- Show confirmed hours versus availability, no denominator guess, and links to actual conflicts
- Compute trials booked/completed and verified enrolments separately
- Finance panel shows CAD collected vs sent/outstanding only where evidence supports; no billing mutation

## Acceptance criteria
- AC1: Teacher load excludes cancelled occurrences and distinguishes scheduled from delivered lessons.
- AC2: Missing teacher availability yields unknown utilization, not 0%/100%.
- AC3: Trial attendance is verified by its actual completion evidence, never clock-time elapsed.
- AC4: Lesson gaps show stable occurrence links, owner, next action and actual source timestamp.
- AC5: Invoice sent/open/paid/refunded are distinguished; only verified paid amounts count as cash collected.
- AC6: All cards have error/partial freshness states and canonical deep links.

## Required test coverage
- T1: Schedule-exception and changed-occurrence aggregation fixtures.
- T2: Attendance/lesson-log mismatch fixtures.
- T3: Paid/unpaid/refund/currency fixtures.
- T4: Desktop/mobile panel browser acceptance and provider outage.

## Explicit non-goals
- No new teacher scheduler, attendance logger, invoicing service or payment processor.
