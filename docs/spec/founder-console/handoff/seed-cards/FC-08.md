# FC-08 — Creation mode backed by the existing marketing work system

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P1  
**Risk:** Medium (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-03, FC-04

## Outcome
A clear creation-mode queue surfaces scripts, filming, edits and the weekly media review without making a second CMS.

## Scope
- Read current Work/Content Library tasks with stages and due dates
- Prioritise open creative deliverables while honouring urgent-lead interruption
- Open canonical task/asset/script via deep link; optional approved one-step status action
- Expose missing metadata and stale sources honestly

## Acceptance criteria
- AC1: Creation mode surfaces next real task, stage, due date, owner, source link and available details.
- AC2: Weekly review task appears if it exists or indicates none found, without auto-creating unrelated tasks.
- AC3: Task completion reflects canonical record and can only update via approved write action.
- AC4: Critical fresh-lead signal can be surfaced but does not silently switch or discard creative work.
- AC5: No recording/publishing happens without separate explicit user choice.

## Required test coverage
- T1: Open/completed/stale task ordering fixtures.
- T2: Browser mode switching and state persistence for a session.
- T3: Confirm creation of no shadow records and no unsolicited publishing API invocation.

## Explicit non-goals
- No complex video editor, content scheduling SaaS, publishing robot.

## Design-stage obligations
Read current repo and Notion schema; map actual files and authorities; confirm dependencies and Risk; use the active `docs/designs/_TEMPLATE.md` for the implementation design on the real card; give each AC a test row; reserve migration/ADR numbers only via current pipeline rules. Never skip human approvals for High risk or migrations. See `03_ENGINEERING/ARCHITECTURE_AND_DATA.md` and `02_DESIGN/VISUAL_DIRECTION.md`.
