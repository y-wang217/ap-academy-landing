# FC-02 — Founder-only same-origin console route and secure app boundary

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P0  
**Risk:** High (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-01

## Outcome
A founder may reach a protected console shell at the chosen path, while everyone else is denied at both render and API access layers.

## Scope
- Implement route per approved architecture; reuse central auth callback and existing sessions
- Use server/data access checks against actual founder permission model
- Render loading/access denied and expiry states, with no student PII leakage
- Reuse present deployment/proxy patterns, avoiding a second auth pool or login

## Acceptance criteria
- AC1: Founder navigation loads the chosen same-origin console route without an independent sign-in flow.
- AC2: Unauthenticated access redirects to central login with safe return path.
- AC3: teacher, student, parent and revoked account cannot retrieve console PII or call console private endpoints.
- AC4: Cookie/session behavior and cross-app navigation remain intact.
- AC5: Test fixtures prove no sensitive data is rendered during failed permission checks.

## Required test coverage
- T1: HTTP and browser tests for founder, guest, teacher, parent, student, revoked account.
- T2: Direct API/data-path permission tests independent of hidden UI links.
- T3: SSO regression + build/typecheck/tests indicated by changed paths.

## Explicit non-goals
- No new signup or third-party identity service; no broad role permission changes.
