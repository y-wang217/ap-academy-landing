# FC-09 — Event-backed actionable signals, interruption policy and integration health

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P1  
**Risk:** Medium (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-05, FC-07

## Outcome
Surface newly actionable leads and actual operational exceptions without false always-on surveillance or interruptions during teaching.

## Scope
- Reuse existing events/realtime/polling where reliable, otherwise bounded polling with freshness
- Implement text-rich new-lead notification and snooze/quiet behavior while in protected delivery mode
- Alerts for stale follow-ups, missing post-trial decision, missing lesson log and provider failures
- Deduplicate, persist as appropriate via existing work records, and link source evidence

## Acceptance criteria
- AC1: A fresh lead arrives at most once per stable source event and remains accessible after snooze.
- AC2: Focus mode and protected teaching time do not auto-call, auto-send or auto-book; deferred alerts are recoverable.
- AC3: Every alert identifies actual source/check time and next action; stale providers cannot claim "all clear".
- AC4: Dismissal means dismissed display, not completed business outcome; unresolved cases persist canonically.
- AC5: Inaccessible alert target does not leak personal information across roles.

## Required test coverage
- T1: Duplicate/out-of-order/offline event fixtures.
- T2: Browser foreground/background, quiet-mode and missed alert recovery flows.
- T3: Failed provider check keeps warning, never silent success.

## Explicit non-goals
- No independent notification platform or unauthorized background phone/messaging activity.
