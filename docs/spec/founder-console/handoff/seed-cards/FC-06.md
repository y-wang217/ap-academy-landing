# FC-06 — Explicit call outcomes, next-action follow-ups and safe queue progression

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P0  
**Risk:** High (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-05

## Outcome
After a real call, the founder can explicitly record a truthful result and scheduled follow-up in the existing authoritative system, then advance the Rolodex.

## Scope
- Use existing write-through adapter/Notion Work/CRM policy where authorized
- Offer safe actions or canonical deep link when no supported write path exists
- Validate idempotency/stale state; read after write; leave unresolved items with owner + next date
- Separate draft message/call notes from any external sending; no auto-send

## Acceptance criteria
- AC1: Founder can choose explicit outcome and due date; server verifies permission and existing authoritative transition.
- AC2: After verified write the queue updates and does not lose unresolved contacts; failed writes remain visible and retry-safe.
- AC3: Duplicate action submits do not create duplicate follow-up cases, or unsupported retries are blocked with verification guidance.
- AC4: "Paid" requires payment/enrolment evidence and cannot be set from verbal consent or trial completion alone.
- AC5: External message/call is never sent merely by opening or logging the case.
- AC6: Mutations produce existing audit/evidence record, with source ID and actual result.

## Required test coverage
- T1: Allowed/disallowed transition matrix and server auth/CSRF-equivalent checks.
- T2: Duplicate submit + timeout-after-commit + read-back recovery tests.
- T3: Browser safe test fixture logs call outcome and proves queue advances and reload persists.

## Explicit non-goals
- No bulk outbound communication, payment writes or appointment modifications.
