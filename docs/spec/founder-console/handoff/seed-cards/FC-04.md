## Outcome
Create a beautiful responsive console shell matching the approved concept, with semantic reusable data surfaces and no hardcoded fictional business results.

## Scope
- Implement static illustrated skyline as separate art layer; panel borders, header, focus rail, mode switch
- Build common Gauge, Radar, Status, InstrumentPanel, Metric, QueueRow and FailureState components
- Implement accessibility, color tokens, responsive 1920/1440/1280/390 breakpoints and reduced-motion
- Use truthful empty/loading placeholders awaiting FC-03 integration; demo data permitted only in isolated preview/tests

## Acceptance criteria
- AC1: Screen has identifiable sunset command-bridge identity, header, main panel grid and physical-instrument trim, without baking data into an image.
- AC2: Sales, Creation and Operations mode tabs are keyboard navigable and reflect selection.
- AC3: All major components have dedicated ready/empty/loading/stale/error variants without fabricated successful data.
- AC4: 1440×900/1920×1080 resemble reference in hierarchy, color and density; captured screenshots attached to PR.
- AC5: 390×844 and 1280×720 keep primary content reachable without sideways scroll.
- AC6: Radar has accessible textual equivalents and honors reduced-motion.

## Required test coverage
- T1: Component visual snapshots for modes + status variants.
- T2: Playwright/screenshots for desktop/laptop/mobile widths and keyboard traversal.
- T3: Automated check for fake hardcoded reference KPIs/names in production sources.

## Explicit non-goals
- No 3D game engine, no decorative buttons presented as working controls.
