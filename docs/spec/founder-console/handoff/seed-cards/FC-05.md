# FC-05 — Sales radar and prioritised next-lead Rolodex

> **SEED ONLY:** Create/match a real Notion Dev Requirements card, obtain the actual REQ ID and preserve existing workflow. Do not treat this text as an approved implementation design.

**Suggested priority:** P0  
**Risk:** Medium (designer must re-evaluate against current code and policy)  
**Initial status:** Backlog  
**Blocked by seed cards:** FC-03, FC-04

## Outcome
Give the founder a real next-best-person-to-call view that retains unresolved leads and explains prioritization.

## Scope
- Implement deduped queue from canonical lead and follow-up data
- Deterministic ranking: new → urgent callback → post-trial → due follow-up → older, respecting opt-outs
- Show selected lead, last verified touch, trial notes/diagnosis, owner, due time, canonical source links
- Filters and keyboard shortcuts; no contact sends in this card

## Acceptance criteria
- AC1: Queue always points to exactly one highest-ranked eligible item or an honest empty/error state.
- AC2: Ranking matches published priority with human-readable reason and stable ordering on ties.
- AC3: Resolved, opted-out and cancelled cases do not repeatedly re-enter; duplicate-source records are handled.
- AC4: Trial diagnosis displayed when available; missing notes shown as missing and never generated as facts.
- AC5: Clicking a link opens the correct canonical record; privacy scope respected.
- AC6: Leads remain queued on network failure or incomplete response; errors are visible.

## Required test coverage
- T1: Table-driven priority tests incl identical timestamps/opt-outs/deduping.
- T2: Integration test with stale provider failure and incomplete pagination.
- T3: Browser founder use: filter, next lead, open record, keyboard navigate.

## Explicit non-goals
- No autonomous calls, texts, AI lead scoring or source record edits.
