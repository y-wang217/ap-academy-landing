# 0067: Schedule Source says the Weekly Schedule is generated, and the owner sees replaced Notion edits
Status: accepted
Date: 2026-10-22

## Context
From adoption on, the scheduler owns a student's Weekly Schedule text in Notion
([0035](0035-weekly-schedule-import-and-summary.md)): `lib/scheduler/summary-sync.ts` replaces any
hand edit with the generated summary and keeps the replaced text in `last_drift_text`. Before
adoption the same field is the import input. Nothing in Notion said which mode a student was in, so
an edit made after adoption looked accepted until the next sync replaced it (readiness finding F02,
REQ-34). The only trace of a replaced edit was a collapsed "Replaced edit" line in the Imported
list, with nothing telling the owner that something new was replaced.

A notice line inside Weekly Schedule is not possible: the monthly billing skill's `parse_slot` reads
every non-empty line of that field and raises on any line that is not a slot, which stops the whole
monthly run (`lib/domain/schedule/monthly-admin-compat.test.ts`).

## Decision
This extends 0035 and does not change its decision.

- **A separate property.** Students & Parents has a text property **Schedule Source**. After
  adoption, every sync writes it one fixed line:
  `Generated by the scheduler since <adoption date>. Edits to Weekly Schedule are replaced. Change classes at <url>`.
  The date is the Toronto date of `schedule_summaries.adopted_at`, so the line only changes when
  the teacher set changes. The link is `/tracker/schedule?staffId=<id>` when every open series has
  one teacher, and `/tracker/schedule?view=all` otherwise. Before adoption the scheduler never
  writes it. Weekly Schedule keeps slot lines only, byte for byte as before.
- **Write-only for the scheduler.** `lib/notion/students.ts` reads Schedule Source in
  `fetchStudentSchedule` only, to skip a write when the line already matches. It is never parsed,
  never a drift input, and never read by billing or the daily task. A hand edit to it is put back
  on the next sync and is not kept.
- **One PATCH.** `writeStudentSchedule` holds the file's only PATCH and sends only the properties
  that differ; `writeWeeklySchedule` is a thin wrapper over it. The outbox payload hash covers the
  text and the line.
- **Drift seen markers.** Migration 0026 adds `last_drift_at` (set with `last_drift_text` whenever a
  sync replaces a hand edit) and `drift_seen_at` to `tracker.schedule_summaries`, under the
  owner-only policies from 0011. A row is unseen when drift text is set and either it was never
  marked seen, or `last_drift_at` is set and later than `drift_seen_at`. Old drift with no time shows
  until it is marked once.
- **The notice.** The Weekly schedules page shows a "Notion edits replaced" card listing unseen rows
  (student, date replaced, the replaced text) and says that a Notion edit does not change the
  calendar. Mark as seen (`POST /api/scheduler/summaries/drift-seen`, owner only) posts each row's
  `lastDriftAt` exactly as the preview returned it, and sets `drift_seen_at = now()` only where
  `last_drift_at` is not distinct from that value. A drift recorded after the page loaded therefore
  stays listed. No path turns drifted text into a series, an exception or any calendar change.

## Alternatives considered
- **A. A marked header line in Weekly Schedule** (`# Generated by the scheduler ...`), with the
  billing skill changed first to skip marked lines. Rejected: it needs a change to a skill outside
  this repo before this card could ship, and any slip stops a monthly billing run.
- **C. No Notion notice, only the owner drift notice.** Rejected: whoever edits Notion would still
  get no signal that the field is generated.
- **One `drift_unseen` boolean** instead of two timestamps. Rejected: it cannot show when an edit was
  replaced, and a race between a sync and Mark as seen could hide a newer drift.
- **Marking seen on page view** (a write inside a GET). Rejected: reads must not write, and the owner
  should acknowledge each replaced edit.

## Consequences
- Each adopted student gets one extra Notion write after release (the first sync writes the line),
  and another only when their open series move between one teacher and several.
- If Schedule Source is renamed or removed in Notion, `fetchStudentSchedule` fails with "Students
  database is missing a needed property"; the sync records `failed` and writes neither property.
  The list paths do not ask for it, so the import preview still loads.
- Revisit if the billing skill learns to skip a header, or if Weekly Schedule stops being a billing
  input.
