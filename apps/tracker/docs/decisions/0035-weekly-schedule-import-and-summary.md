# 0035: Weekly Schedule import is all or nothing per student, and the text field becomes a generated summary
Status: accepted
Date: 2026-10-14
## Context
Students' recurring classes live as free text in Weekly Schedule on Notion's Students & Parents. The monthly billing run (the `ap-academy-monthly-admin` skill) reads that text. Scheduler cards 4/8 to 8/8 need the same classes as real series, with one authority afterwards. The skill's `parse_slot` reads the part before the first `|`, takes the next field as the course, ignores later fields, and raises on any non-empty line it cannot match, which stops the whole run.
## Decision
- **All or nothing per student.** A student is adopted only if every line parses and resolves to exactly one active teaching staff member. One bad line holds back all of that student's lines; the repair list shows each line with `ok` or a reason code. Partial adoption would make the generated summary silently drop billed slots.
- **Teachers by exact full name only.** Matched against Staff, ignoring case and spacing. A first-name match is a hint, never applied. Student `Owner` and `Trial Teacher` are never read (their meaning changes by pipeline stage); the Notion parse schema has no such keys and a test scans the source.
- **Deterministic request IDs.** `request_id` is a SHA-1 based UUID over the org, the student page ID and the normalised line, so a rerun or a retry inserts nothing. `tracker.adopt_student_schedule()` inserts the series and the `schedule_summaries` row in one transaction; a repeat returns the existing row.
- **Generated summary.** After adoption the scheduler writes Weekly Schedule: one slot line per weekly series, `Day HH:MM-HH:MM | Course | Teacher`, with no header or notes. Future-effective changes go in later fields, `| from YYYY-MM-DD` and `| until YYYY-MM-DD`, which the current parser ignores. A TypeScript copy of `parse_slot` in the tests checks every rendered line and the round trip.
- **Regeneration points.** After adoption, after creating a class, and after a "This class and future" split (both students if the student changes). A single-occurrence move or cancel never touches Notion. A write is skipped when the text is unchanged. A failed write never fails the class write: the response carries `summarySync: "failed"`, the row records the error, and `POST /summaries/sync` retries.
- **Overwrite on drift.** Notion cannot lock a field. If the text differs from what the scheduler last wrote (or the legacy text before the first write), the sync overwrites it and keeps the replaced text in `last_drift_text`, shown on the admin page.
- **Exceptions through a review list, not the text.** Cancelled and moved classes, one-offs, `from`/`until` dates and an unsynced or stale summary appear on `GET /monthly-review` for Charlie, who already confirms makeups and cancellations when running billing.
- **New classes for a non-adopted student.** Refused with `409 legacy_schedule_pending` if the legacy text is non-empty; adopted on the spot if it is empty.
- **Narrow Notion access.** Three properties are requested (property IDs are looked up from the data source schema, since `filter_properties` takes IDs), everything else is dropped at the parse step, names are never written to Postgres, and the only write is one PATCH of `Weekly Schedule`.
## Alternatives considered
- Partial adoption of clean lines: risks silent billing loss.
- A teacher picker in the repair list: an in-app write path and editing UI, about a day more, outside this card.
- Appending exceptions to the text: the current parser would raise or miscount.
- A separate Notion token for this database: more to rotate; the same token with a wider grant was chosen (Charlie to confirm).
## Consequences
Migration 0011 needs Charlie's sign-off before it reaches the live database. The integration needs read and update on Students & Parents, and the Weekly Schedule description should become "Generated by the tracker scheduler. Edits are overwritten." Until the monthly admin skill honours `from`/`until`, a month in which a split takes effect counts both lines for the whole month; the review list flags those students. Freshly imported lines whose first date is after today carry `| from <date>` until the next sync after that date. Revisit if more fields than Weekly Schedule need to be generated, or if the skill moves into this repo.
